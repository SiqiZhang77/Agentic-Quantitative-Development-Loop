# E4V3 T3 可分批选择的四条件实验协议

E4V3 比较四个固定条件：`M0R0`（单Agent、无项目记忆）、`M0R1`（单Agent、有项目记忆）、`M1R0`（Manager-Star、多角色、无项目记忆）和 `M1R1`（Manager-Star、多角色、有项目记忆）。每条观察仍使用相同T3题目、相同模型、相同容器、两次尝试上限、每次尝试20次模型调用上限和500,000 token上限。

冻结配置只登记一个可用实验编号池：四个条件各有15个互不重复的编号，共60条潜在观察。它不要求操作者在冻结前决定最后运行10次还是15次，也不要求一次启动全部条件。

每次启动时，操作者明确选择一至四个条件、起始编号和本次连续运行的编号数量。比如可以只运行`M1R1`的K1；之后运行同一条件的K2至K10；也可以把四个条件的K1至K10放在一条命令中交错运行。混合条件时，程序沿用冻结表中的顺序，避免某个条件总在同一时间位置；单一条件时则按选中的编号顺序运行。

只有本次实际选中的条目需要全部通过零模型预检；之后程序先把本次选择写入独立记录，再允许输入模型密钥并串行运行。某条观察发生工作流失败、答案缺失或评分异常时，该条原始记录和评分都会保存；控制器继续处理本批次之后已选择的条目，不删除失败条目，也不补造答案。

同一个实验编号只能形成一条正式观察。程序会在调用模型前检查远端目标分支和本地观察目录；已经运行过的编号不会被覆盖或再次使用。分批选择会保留研究灵活性，但如果根据中途结果决定何时停止，论文必须如实说明这是顺序追加样本，而不是声称最终样本量在第一次运行前已经固定。E4V3由新的agreement和新的运行身份组成，绝不改写或重命名已冻结的E4V1/E4V2观察。
